The durable-projection contract this must satisfy is explicit in the scoped helper it depends on — `extensions/goal-loop-core.ts:3216-3240` (`releaseLoadHoldDurably`), the 2026-10-19 fix for exactly this drift class:

`updateGoal` has no equivalent restore: when `persistState` returns false, `state.goal` stays the NEW goal in RAM while `active.jsonl` still holds the OLD one, and `AGENTS.md` forbids exactly that ("never let live state drift from its durable projection"). Note this is a DIFFERENT site from the 2026-10-19 `releaseLoadHoldDurably` fix (which was about the load-hold gate); here the same class of drift exists on the generic goal-update path, and the 2026-10-19 fix's own comment ("so no caller can announce a release the durable state does not carry") is the contract being violated.

Fix direction: on `persistState` failure, restore the previous `state.goal` (and re-`writeGoalMd` the old goal) — or make `updateGoal` snapshot/restore like `releaseLoadHoldDurably` does.

### MEDIUM — `setGoal` reports success and clears the transaction journal even when the state ledger write failed
`extensions/loops/goal-orchestrator.ts:1004-1022` (the `setGoal` tail) treats the goal as committed on the strength of the markdown + state write, but the durability contract is "the return contract":

Two things contradict each other here:
- `appendLedger(ctx.cwd, "goal_created", …)` is emitted UNCONDITIONALLY, i.e. the journal claims a goal was created even when `stateLanded` is false and the durable `active.jsonl` never received the new goal. A journal row ("goal_created") that the snapshot (`readState` → `extensions/goal-loop-core.ts:3019`) contradicts is exactly the "ledger row claims a state the snapshot contradicts" class named in the hunt list.
- `setGoal` ALSO archives the predecessor goal before this write (`extensions/loops/goal-orchestrator.ts:963-975`, `archiveCurrentGoal(...)` then `goal_superseded_unarchived`), so a failed state write leaves the old goal archived and the new goal absent from the ledger — the work item exists nowhere durable.

The scoped journal writer's contract — the state line is the durable projection that `readState` adopts (`extensions/goal-loop-core.ts:3432-3443`, `appendLedger` → `type:"state"` line; `readState` at 3019-3160 merges only `type === "state"` records) — means a `goal_created` row without a matching `state` line is a row the snapshot contradicts.

Fix direction: emit `goal_created` only when `stateLanded` (or add a distinct `goal_created_unpersisted` row), and treat a failed `stateLanded` as a refusal rather than a success-with-warning.
