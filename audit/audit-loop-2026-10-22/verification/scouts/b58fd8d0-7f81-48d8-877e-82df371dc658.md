**Where:** `scripts/run-tests.mjs:38` (defect) vs `package.json:34-49`, `package.json:61`, `README.md:364-365`, `tests/release-contract.test.ts:76` + `:138`, `scripts/release-pack-smoke.mjs:46-76`.

**Code (the defect):**
> `scripts/run-tests.mjs:38` — `import { SLOW_TEST_FILES } from "../tests/slow-files.mjs";`

**Contradicting consumer/contract:**
> `package.json:34-49` — `"files": [ "extensions", "skills", "prompts", "schemas", "scripts", "docs", "examples", "media", "README.md", … ]` (no `tests` entry)
> `package.json:61` — `"test": "node scripts/run-tests.mjs"` (this script ships in the manifest)
> `README.md:364-365` — "The package ships extensions, skills, prompts, schemas, **scripts**, docs, examples, media and top-level user documentation. The full test suite remains **repository material**"
> `tests/release-contract.test.ts:76` — `assert.ok(dryRunFiles().has("scripts/run-tests.mjs"), "the hardened runner must ship in the tarball");`
> `tests/release-contract.test.ts:138` — `assert.equal([...dryRunFiles()].some((file) => file === "tests" || file.startsWith("tests/")), false, "tests remain repository-only material");`

The two release-contract assertions are individually true and jointly false: the gate *requires* the
runner to ship and *forbids* the only module it imports, so the shipped runner is dead on arrival.
`scripts/release-pack-smoke.mjs` required[] (lines 46-76) lists `"scripts/run-tests.mjs"` but never
`tests/slow-files.mjs`, nor the runner's other unpinned imports `"scripts/host-contention.mjs"`
(run-tests.mjs:39) and `"scripts/test-failure-diagnostics.mjs"` (run-tests.mjs:37) — presence-only
tar checks, no import check.

**Proof (read-only):**
- Green v0.39.44 gate log `audit/patch-release-0.39.44-2026-10-21/release-check-final.log:2803` —
  `(pass) release contract: changed tests ride the hardened runner` — and the same log's pack manifest
  (`npm notice total files: 205`) contains **0** `tests/` entries.
- Empirically reproduced against a package-shaped tree (scripts/ only, no tests/):
  `IMPORT FAILED: ERR_MODULE_NOT_FOUND Cannot find module '…/package/tests/slow-files.mjs' imported from …/package/scripts/run-tests.mjs`.

**Impact:** `npm test`, `npm run test:all` and `npm run release:check` inside an installed
`pi-goal-list-loop-audit` abort with ERR_MODULE_NOT_FOUND, and no release lane can see it.

**Fix direction:** move `SLOW_TEST_FILES` into a shipped module (e.g. `scripts/slow-files.mjs`) or
add `tests/slow-files.mjs` to `files`, pin the runner's whole import set in the smoke `required[]`,
and add a gate step that *imports* the installed `scripts/run-tests.mjs` from the disposable prefix.

> `.github/workflows/real-host-canary.yml:25-27` —

> `.github/workflows/real-host-canary.yml:3` — `workflow_dispatch:` (the operator may select any branch/tag)

**Contradicting consumer:**
> `scripts/real-host-canary.mjs:50` — `env: { ...process.env, GLLA_GLOBAL_SETTINGS_PATH: settings, PI_CODING_AGENT_DIR: agentDir }`

The env of the step that runs the dispatched ref's `scripts/real-host-canary.mjs` is handed verbatim
(`...process.env`) to the child it spawns, and that child loads the dispatched ref's
`extensions/loops/goal.ts`. The secret boundary is therefore the *ref*, not the workflow file — a
contributor with push-but-not-merge rights can dispatch the (default-branch) canary workflow on their
own branch and read `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`, without ever touching `.github/workflows/`.

**Fix direction:** pin the canary checkout to the default branch (`ref: ${{ github.default_branch }}`)
or move the keys behind a protected environment whose deployment branch rule excludes feature branches.

### F3 — LOW — The stall watchdog's "extend" branch can *shrink* the window, and the initial window ignores the module's own ceiling
**Where:** `scripts/run-tests.mjs:95-99` and `:128` vs `scripts/run-tests.mjs:87-89` and `:272-273`, with `scripts/host-contention.mjs:37`.

**Code (the defect):**
> `scripts/run-tests.mjs:95-99` — `stallTimeoutMs()` → `return Math.ceil(DEFAULT_STALL_TIMEOUT_MS * contentionFactor());`
> (unclamped by `MAX_STALL_TIMEOUT_MS`; with `scripts/host-contention.mjs:37` `MAX_CONTENTION_FACTOR = 8`
> this yields 180 000 × 8 = **1 440 000 ms**)
> `scripts/run-tests.mjs:128` — `return { action: "extend", limitMs: Math.min(limitMs * Math.min(factor, 4), maxTimeoutMs) };`
> → with `limitMs = 1 440 000` and `maxTimeoutMs = 900_000` the "extend" action returns **900 000**, i.e. *less* than the window it was given.

**Contradicting contract:**
> `scripts/run-tests.mjs:87-89` — "**v0.39.43: the stall window may be extended when the host is measurably slow (see the watchdog), but never without bound** … `export const MAX_STALL_TIMEOUT_MS = 900_000;`"
> `scripts/run-tests.mjs:272-273` — `stallLimit = decision.limitMs; log(\`stall window extended to ${…}s — the host is contended …\`)` — the log claims "extended" while the value shrank from 1440 s to 900 s.

**Impact:** on a maximally contended host the watchdog may stay silent for 24 minutes (past the
declared 15-minute ceiling) and then, on the extension path, kill a slow-but-alive suite *earlier*
than the window it had already granted. False-late and false-red, never false-green.

**Fix direction:** clamp the initial window with `MAX_STALL_TIMEOUT_MS` in `stallTimeoutMs()` and make
the extend branch monotonic (`Math.max(limitMs, …)`).

> `.github/workflows/publish.yml:131-141` — the only tag check is `if (process.env.RELEASE_TAG !== expected) throw new Error(\`release tag … does not match package.json …\`)`
> (no ancestry/provenance check against the default branch)

**Contradicting contract:**
> `docs/RELEASING.md:64-65` — "The sync daemon owns source/evidence commits. Do not amend, reset or rebase its commits; **a release tag must point at the reviewed, validated source**."

**Impact:** a release can be published from a tag on any commit in the repository (e.g. a

**Fix direction:** before publishing, assert the tag commit is an ancestor of `origin/main`
(`git merge-base --is-ancestor <sha> origin/main`) in the "Verify the tag" step.
