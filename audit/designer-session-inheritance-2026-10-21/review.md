### Findings

- **P2 — thinking-only Designer pin is not independent of the session dial** (`extensions/designer-model.ts:72-77`): `config.thinking` is ignored on the session route, so `designerThinkingLevel` without `designerModel` never reaches the file. Deliberate and test-locked (`tests/designer-settings.test.ts:302-328`), and unreachable from the Designer tab — but the objective's "keep explicitly selected Designer model/thinking settings independent" holds only for the model-selected case. Smallest fix if wanted: `thinking: config.thinking ?? ctx.thinkingLevel` on the session route, plus the corresponding test change. Not a regression of this repair.
- **P2 — a workflow-script Designer launch is not an explicit role request** (`extensions/designer-registration.ts:44-51`): `workflow: true` / script-file launches are invisible to `requestsDesigner`, and pi-subagents ships no `Designer.md` (`node_modules/pi-subagents/agents/`), so an on-demand Designer is not registered for that path. Consistent with the audit's "scripts never opt the role in" rule, but a real functional edge.
- **P2 — refresh failures are silent** (`extensions/designer-registration.ts:101-104`): a write failure returns "absent" with no ledger/notify, so the launch fails as "unknown agent" with no GLLA diagnostic.
- **P2 — the projection is global** (one `Designer.md` for the whole agent dir; child sessions are excluded by the foreign-session guard at `goal-activation.ts:3581,3634`), so a nested launch inherits the main host's pair. Already documented in the audit README's Limits.
- **P2 — wording nit**: `designerProjectionNote` always says "the pair comes from the /glla Designer pin or the live session" even when the pair is purely session-derived (`extensions/goal-loop-subagents.ts:158-166`). It never claims a saved pin, so obligation (c) holds.
- **Informational**: `extensions/loops/goal-list-queue.ts:239` imports `syncSubagentModelOverrides` without using it (pre-existing; `tsconfig` has no `noUnusedLocals`, so `npm run check` will not flag it).
- **No P0/P1 defect found.** The two writers of the managed file agree byte-for-byte (`goal-loop-subagents.ts:299-303` and `:384` both use `designerProjectionNote`), and the companion's discovery cache is fingerprint-based on file size+mtime (`node_modules/pi-subagents/src/agents/agents.js:2245-2256,2403-2412`), so a rewritten `Designer.md` is re-discovered at the next launch rather than served from a stale cache.
